## 起動方法

ビルド成果物がそのままアプリなので、**`index.html` をブラウザで開くだけ**。

```bash
# ローカル確認
CBVER=120 node build.js && open index.html
```

公開版： https://kshimizu7.github.io/cardbattle/

> `file://` で開くと端末によっては `localStorage` が効かず、戦績が保存されない。
> セーブまで確かめたいときは Pages 経由で開く。

## ビルド方法

```bash
CBVER=120 node build.js
```

出力は3つ。

| 出力先 | 用途 | Git |
|---|---|---|
| `index.html` | GitHub Pages 用 | ○ コミットする |
| `ArcanaClash.html` | Drive の最新版用 | × `.gitignore` |
| `dist/ArcanaClash_v120.html` | Drive の `版/` 用 | × `.gitignore` |

- `CBVER` がタイトル画面下部の `ver 120` になる。**中身を変えたら必ず上げる**。
  **省略すると既定値の `21` になる**ので、ビルドのときは必ず付ける
- `build.js` は内部で `tools/rpgexp.js` を子プロセス実行する（RPGモードのページを生成）。ここが失敗するとビルドが止まる
- `art/cut/*.webp` を base64 で全部埋め込むため、出力は 8MB 前後になる

### 復元

`index.html` にはソース一式がそのまま埋まっている。`src/` を失っても完全復元できる。

```bash
node recover.js                          # index.html から
node recover.js path/to/ArcanaClash.html # 任意のビルド済みHTMLから
```

## テスト方法

```bash
node smoke.js            # 画面の通し確認（Playwright・18項目・約7秒）
node rulecheck.js 300    # 戦闘ルールの回帰（ブラウザ不要・600戦・約20秒）
node sim.js 2000 hard    # キャラ別の勝率バランス
node sim3.js starter     # プール別バランス
node sim2.js             # カード単体の強度
node diffcheck.js        # CPU難易度差の検証
node tools/dbcheck.js    # 台帳CSVとエンジンのズレ検査
```

**配信前に必ず通すのは `smoke.js` と `rulecheck.js` の2つ。**

`rulecheck.js` の現在の検査項目：

- 凱歌（敵を倒すともう一度行動）が繰り上がりを挟んでも必ず発動する
- 撃った弾が「もう倒れている相手」に吸い込まれて不発にならない
- 繰り上がりのせいで同じ相手を二重に殴らない
- 「最弱を狙う」技が、画面の予告（`E.weakestOf`）と同じ相手に当たる
- 献身で助かったとき、必ず「一度倒れた合図」が出ている

> **注意：** テストスクリプトの多くが Playwright を絶対パス
> `/root/.npm-global/lib/node_modules/playwright` で `require` している。
> 別のマシンで動かすときはここを直す必要がある（既知の弱点）。

## 配信手順

**PC → Google Drive → GitHub の3か所へ同時に反映する。**どれか1つだけにしない。

```bash
# 1. ビルド（クラウド側）
CBVER=NN node build.js

# 2. テスト
node smoke.js && node rulecheck.js 300

# 3. 変更履歴.md を日本語で更新

# 4. コミット（クラウド側のローカルリポジトリ）
git add -A
git -c user.name=kshimizu7 \
    -c user.email=70817205+kshimizu7@users.noreply.github.com \
    commit -m "vNN: 〜"

# 5. 差分だけをアーカイブにまとめる（削除ファイルは除く）
git diff --name-only --diff-filter=d HEAD~1 HEAD -z | xargs -0 tar czf /tmp/_vNN.tgz
```

そのあと、PC と Drive へ転送する。

| 送り先 | ファイル |
|---|---|
| `C:\Users\kazu_\projects\cardbattle\_vNN.tgz` | 差分アーカイブ |
| `G:\マイドライブ\バトルゲーム\ArcanaClash.html` | 最新版（上書き） |
| `G:\マイドライブ\バトルゲーム\版\ArcanaClash_vNN.html` | 版として保存 |

最後に PC 側で展開して push する。

```bash
cd "$HOME/mnt/cardbattle"
tar xzf _vNN.tgz --overwrite
export GIT_DIR=$HOME/cb-gitdir GIT_WORK_TREE=$HOME/mnt/cardbattle
git add -A
git -c user.name=kshimizu7 \
    -c user.email=70817205+kshimizu7@users.noreply.github.com \
    commit -m "vNN: 〜"
git -c credential.helper=store push https://github.com/kshimizu7/cardbattle.git HEAD:main
```

## PC側 Git の特殊構成

**普通の構成ではないので注意。**

- 作業ツリー … `C:\Users\kazu_\projects\cardbattle`
- リポジトリ本体（`.git`）… **作業ツリーの中になく、`$HOME/cb-gitdir` にある**

そのため、PC側で git を使うときは**毎回この2つを明示する**。

```bash
export GIT_DIR=$HOME/cb-gitdir GIT_WORK_TREE=$HOME/mnt/cardbattle
```

これを忘れると「リポジトリではありません」と言われる。

認証情報は `$HOME/.git-credentials`（`credential.helper=store`）。
**リポジトリの中には絶対に置かない。**

## クラウド側は detached HEAD

Claude が作業するクラウド環境の `/root/cardbattle` は、
`origin/main` から切り離された **detached HEAD** の状態で運用している。

- クラウド側でも commit はするが、**push は必ず PC 側から行う**
- クラウド側から直接 push しない（過去にプロキシの 403 で失敗した経緯もある）
- クラウド環境は破棄されうるので、**クラウド側だけに残っている変更を作らない**

## 絵の加工パイプライン

キャラ絵は ChatGPT で描き、**マゼンタ（#FF00FF）背景**で書き出してから取り込む。
順序と役割は次のとおり。

```bash
python3 tools/keyout.py  <sheet.png> <id> [<id>...]   # マゼンタを抜いて切り抜きにする
python3 tools/despill.py <id> [--width N --thr N]     # 紫の縁と、内側に残った点を消す
python3 tools/cut2webp.py <id> [<id>...]              # art/cut/<id>.webp を作る
python3 tools/facemock.py out.png <id> [<id>...]      # ゲームと同じ計算で実寸確認
```

- `facemock.py` は**ゲーム本体と同じ `fitFace` の計算**で 136px（盤面）と 352px（図鑑）に切り出す。
  「実寸で見てどうか」を判断するときは必ずこれを使う
  （`tools/layermock.py` は全身を収める別物で、実寸判断には使えない）
- 新しいキャラを足したら `art/face.json` に**目の位置**の行を追加する（既存行は触らない）
- 絵のプロンプトは `docs/キャラ絵プロンプト.txt` と `docs/共通指定.txt` に蓄積している

## 実機確認が必要な項目

**Playwright では再現できない**ため、kazu の端末（Android）での確認が唯一の検証手段になるもの。

| 項目 | 理由 |
|---|---|
| セーフエリア（カメラ穴・丸い角） | `env(safe-area-inset-*)` はエミュレータでは 0 のまま |
| 端末の「文字サイズ」設定 | Chrome の Text scaling が CSS の px を膨らませる。技名の折り返しはこれが原因だった |
| 日本語の縦書き（`writing-mode`） | 端末のフォントによって効かないことがある |
| `localStorage` の可否 | `file://` では端末により保存されない |
| 全画面・ホーム画面追加 | ブラウザと端末の実装差が大きい |
| 実際のタップ精度 | 押しやすさ・誤タップは実機でしか分からない |

配信後は「この3点を見てほしい」と具体的に依頼し、スクリーンショットで確認する。
