## 起動方法

ビルド成果物がそのままアプリなので、**`index.html` をブラウザで開くだけ**。

```powershell
# ローカル確認
$env:CBVER = '120'
node .\build.js
Start-Process .\index.html
```

公開版： https://kshimizu7.github.io/cardbattle/

> `file://` で開くと端末によっては `localStorage` が効かず、戦績が保存されない。
> セーブまで確かめたいときは Pages 経由で開く。

## ビルド方法

```powershell
$env:CBVER = '120'
node .\build.js
```

出力は3つ。

| 出力先 | 用途 | Git |
|---|---|---|
| `index.html` | GitHub Pages 用 | ○ コミットする |
| `ArcanaClash.html` | Drive の最新版用 | × `.gitignore` |
| `dist/ArcanaClash_v120.html` | Drive の `版/` 用 | × `.gitignore` |

- `CBVER` がタイトル画面下部の `ver 120` になる。**中身を変えたら必ず上げる**。
  **省略すると既定値の `21` になる**ので、ビルドのときは必ず付ける
- `build.js` は内部で `tools/rpgexp.js` を子プロセス実行する（RPGモードのページを生成）。ここが失敗するとビルドが止まる
- `tools/rpgexp.js` は入力の CRLF / CR を LF に正規化するため、Windows/Linuxで同じRPG内容を生成できる
- `art/ui/frame_t1.webp`〜`frame_t3.webp` はbuild必須素材としてGitで追跡する
- `art/cut/*.webp` を base64 で全部埋め込むため、出力は 8MB 前後になる
- v120時点で、通常clone単体からの再buildを確認済み

### 復元

`index.html` にはソース一式がそのまま埋まっている。`src/` を失っても完全復元できる。

```powershell
node .\recover.js                          # index.html から
node .\recover.js path\to\ArcanaClash.html # 任意のビルド済みHTMLから
```

## テスト方法

```powershell
node .\smoke.js             # 画面の通し確認（Playwright・18項目・約7秒）
node .\rulecheck.js 300     # 戦闘ルールの回帰（ブラウザ不要・600戦・約20秒）
node .\tools\sim3.js 2000 starter # プール別バランス（必要なとき）
node .\tools\dbcheck.js     # 台帳CSVとエンジンのズレ検査（必要なとき）
```

**配信前に必ず通すのは `smoke.js` と `rulecheck.js` の2つ。**

`rulecheck.js` の現在の検査項目：

- 凱歌（敵を倒すともう一度行動）が繰り上がりを挟んでも必ず発動する
- 撃った弾が「もう倒れている相手」に吸い込まれて不発にならない
- 繰り上がりのせいで同じ相手を二重に殴らない
- 「最弱を狙う」技が、画面の予告（`E.weakestOf`）と同じ相手に当たる
- 献身で助かったとき、必ず「一度倒れた合図」が出ている

### Playwrightの準備

`package.json` は作らず、Playwrightは母艦PC側のグローバル開発ツールとして管理する。
製品コードと生成HTMLには依存を入れない。

```powershell
npm install --global playwright
playwright install chromium
[Environment]::SetEnvironmentVariable(
  'CARDBATTLE_NODE_MODULES',
  (npm root --global),
  'User'
)
```

設定後はCodexとPowerShellを新しく起動する。必須テストの `smoke.js` は
`tools/playwright-loader.js` を通じて、まず通常の `require('playwright')`、
次に `CARDBATTLE_NODE_MODULES` 配下のPlaywrightを探す。この構成はWindows/Linux共通。
ほかのPlaywright利用スクリプト4本の共通ローダー移行は未完了。

## 配信手順

正式な作業場所は母艦Windows PCの通常clone。

```text
C:\Users\kazu_\projects\cardbattle-main
```

**配信はkazuの明示承認後だけ行う。** GitHub、Google Drive、公開版の一部だけを
先に更新せず、版番号と成果物をそろえて進める。

```powershell
# 1. mainを最新化し、作業ツリーがcleanであることを確認
git fetch origin
git status
git pull --ff-only origin main

# 2. 版番号を明示してbuild
$env:CBVER = 'NN'
node .\build.js

# 3. 必須テスト
node .\smoke.js
node .\rulecheck.js 300

# 4. 変更履歴.md を日本語で更新し、kazuの確認を受ける

# 5. commitとpush
git add -- <確認済みの対象ファイル>
git commit -m "vNN: 〜"
git push origin main

# 6. ローカルとGitHubの一致を確認
git fetch origin
git status
git rev-parse HEAD
git rev-parse origin/main
```

commit identityはグローバル設定を変えず、このリポジトリにだけ設定する。

```powershell
git config --local user.name kshimizu7
git config --local user.email 70817205+kshimizu7@users.noreply.github.com
```

GitHubへの保存確認後、承認された同じbuild成果物をDriveへ配置する。

| 配置先 | ルール |
|---|---|
| `G:\マイドライブ\バトルゲーム\ArcanaClash.html` | 正式最新版として上書き |
| `G:\マイドライブ\バトルゲーム\版\ArcanaClash_vNN.html` | 過去版として新規保存。既存版を上書きしない |
| `G:\マイドライブ\バトルゲーム\変更履歴.md` | リポジトリ正本の写しを更新 |

コピー前後に版番号、ファイル名、サイズまたはSHA-256を照合する。

## 正式開発環境とGit運用

| 項目 | 内容 |
|---|---|
| 実行環境 | 母艦Windows PC ＋ Codex |
| 作業コピー | `C:\Users\kazu_\projects\cardbattle-main` |
| branch | `main` |
| Git構成 | `.git` を作業コピー内に持つ通常clone |
| 正本 | GitHubの `main` |

### 正本は GitHub の `main`

**環境間の正本もGitHubの `main` だけ。** ローカルファイルの直接コピーや
tgz転送、別環境での再commitは行わない。同じテーマを複数環境で同時編集しない。

### 通常の作業手順

**作業を始める前：**

```powershell
git fetch origin
git status          # 未 commit の変更が無いことを確認する
git pull --ff-only origin main
```

**作業が終わったあと：**

1. この通常cloneでcommitし、`git push origin main` を実行する
2. **GitHub 上で反映されたことを確認する**（`git log --oneline -1` が push 先と一致するか）
3. **そのあとで**もう一方の環境を `git pull` して最新化する

### やってはいけないこと

- **未 commit の変更が残っている状態で、もう一方の環境へ同じ作業を依頼しない。**
  片方の未保存の変更を、もう片方が知らずに上書きする事故になる
- 複数環境で同じファイルを並行して直す
- `main` を経由せずにファイルを手渡しする

## 絵の加工パイプライン

キャラ絵は ChatGPT で描き、**マゼンタ（#FF00FF）背景**で書き出してから取り込む。
順序と役割は次のとおり。

```bash
python3 tools/keyout.py  <sheet.png> <id> [<id>...]   # マゼンタを抜いて切り抜きにする
python3 tools/despill.py <id> [--width N --thr N]     # 紫の縁と、内側に残った点を消す
python3 tools/cut2webp.py <id> [<id>...]              # art/cut/<id>.webp を作る
python3 tools/facemock.py out.png <id> [<id>...]      # ゲームと同じ計算で実寸確認
```

- `facemock.py` は**ゲーム本体と同じ `fitFace` の計算**で 136px（盤面）と 352px（図鑑）に切り出す。
  「実寸で見てどうか」を判断するときは必ずこれを使う
  （`tools/layermock.py` は全身を収める別物で、実寸判断には使えない）
- 新しいキャラを足したら `art/face.json` に**目の位置**の行を追加する（既存行は触らない）
- 絵のプロンプトは `docs/キャラ絵プロンプト.txt` と `docs/共通指定.txt` に蓄積している

## 実機確認が必要な項目

**Playwright では再現できない**ため、kazu の端末（Android）での確認が唯一の検証手段になるもの。

| 項目 | 理由 |
|---|---|
| セーフエリア（カメラ穴・丸い角） | `env(safe-area-inset-*)` はエミュレータでは 0 のまま |
| 端末の「文字サイズ」設定 | Chrome の Text scaling が CSS の px を膨らませる。技名の折り返しはこれが原因だった |
| 日本語の縦書き（`writing-mode`） | 端末のフォントによって効かないことがある |
| `localStorage` の可否 | `file://` では端末により保存されない |
| 全画面・ホーム画面追加 | ブラウザと端末の実装差が大きい |
| 実際のタップ精度 | 押しやすさ・誤タップは実機でしか分からない |

配信後は「この3点を見てほしい」と具体的に依頼し、スクリーンショットで確認する。
