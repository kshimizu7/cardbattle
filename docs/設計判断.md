# 設計判断

コードを読んでも理由が分からない判断を残す場所。
**「なぜそうなっているのか」を知らずに触ると壊れる**ものだけを書く。

## fitFace を横方向に拡大できない

**結論：盤面のキャラは、横方向には絶対に大きくできない。**

`src/ui.js` の `fitFace()` は、絵の拡大率を

```js
var s = Math.max(w / iw, h / ih) * FACE_AT.zoom;
```

で決める。盤面は **3列固定**なので、1マスの幅は「画面幅 ÷ 3」で決まってしまい、
`w / iw` が常に支配的になる。つまり**拡大率は幅で決まる**。

そのため「キャラをもっと大きく見せたい」という要望に対してできるのは**縦に伸ばすことだけ**で、
実際 v112 でマスを 122×122 → 122×159 にして（縦に約30%）、
胸のあたりで切れていた絵が腰の下まで見えるようにした。**顔そのものの大きさは変わっていない。**

横に大きくするには盤面を3列から変えるしかなく、それはゲームの根幹（前衛3・後衛3）を壊す。
**この議論は何度も出ているので、要望が来たらこの節を示すこと。**

関連：`FACE_AT = { x:0.5, y:0.30, zoom:1.25 }` は
「両目の中間（`art/face.json`）を、箱の左右中央・上から30%に置く」という意味。
v102 で顔の中心基準から**目の基準**に変えた。

## 「一番弱い」の定義

暗殺者の**死の刻印**（`range:'weakest'`）と**首狩り**が狙う相手の決め方。

上から順に比べ、**差がついたところで決定**する。

| 順 | 条件 |
|---|---|
| ① | 残りHPが少ない |
| ② | 脅威が高い（攻撃×2＋素早さ。支援職 +10／魔法職 +8／号令系の特殊能力持ち +6） |
| ③ | 最大HPが少ない |
| ④ | 前衛が先 |
| ⑤ | 左が先 |

④⑤まで下りれば**必ず一意に決まる**（同じマスに2体はいないため）。
配列の並び順やブラウザの `sort` の実装に左右されない。

**②を入れている理由：**「弱った危険人物から刈る」という暗殺者らしさを残すため。
プレイヤーには脅威度の数字が見えないが、ハイライトが必ず真実を指すので予測する必要がない。

### 実装上の鉄則

この判定は **`engine.js` の `weakestOf()` ただ1つ**に置き、
エンジン・画面のハイライト・CPUの読みの**3者が必ずこれを呼ぶ**。

v116 まではこの式が3か所に別々に書かれていて、残HPが並ぶと
**「光っているのは騎士なのに、実際に殴られるのは僧侶」**というズレが出ていた。
首狩りの即死が別のキャラに飛ぶこともあった。v117 で1つに統合し、
`rulecheck.js` に「最弱狙いが予告どおりの相手に当たる」を追加して再発を止めている。

## チーム名は「決定的に」生成する

`src/teamname.js`。名前は**編成の中身から決まり、陣営（青／赤）では決まらない**。
聖騎士だらけなら、自軍でも敵軍でも「黎明の誓約」を名乗る。

### 決定的であること

IDを**並べ替えてから**種（ハッシュ）を作る。そのため

- 同じ6体なら、置いた順番に関係なく**必ず同じ候補が同じ順番**で出る
- 1体入れ替えれば変わり、**戻せば元の名前に戻る**

**乱数で引き直す方式にしなかった理由：** 編成は1体置くたびに変わるので、
乱数だと「さっきの名前の方がよかったのに戻せない」が頻発する。
⟳ は「引き直し」ではなく **1→2→3→4→5→1 の巡回**にしてあり、必ず前の候補に戻れる。

### 候補が似通わないようにする

修飾語×核の組み合わせから上位を取るだけだと
「黎明の誓約／黎明の盟約／黎明の誓い」のように差のない5個になる。
**同じ修飾語・同じ核が3回以上出ないよう間引いて**、見て違いが分かる5個にしている。

### 相手と同じ名前にしない

- 相手と同名になる候補は、⟳ の巡回から**黙って飛ばす**（エラーを出さない）
- **ずらすのは常に後から確定した側**（CPU または P2）。
  **人が決めた名前は絶対に動かさない**
- ミラー編成（候補がそっくり同じ）のときは、**核ではなく修飾語をずらす**。
  「白銀の誓約」と「聖灰の誓約」のように末尾がそろっている方が対決らしく見えるため
- ただし**手入力で同じ名前にした場合はそのまま通す**。本人が選んだものを書き換える方が不親切

### 陣営で語彙を分ける案は撤回した

一度「自軍＝聖なる語／敵軍＝葬送の語」に分ける案を採ったが、
**双方が聖騎士編成なのに片方が「葬列」になる**のは名前が編成を語っていない＝嘘になる。
敵らしさは**色と紋章がすでに担当している**ので、言葉まで敵役を演じる必要はない。

## 技名カットインは折り返さず、字を縮める

`techRibbon()` は、札を出したあとに**実測して**入りきらない分だけフォントを小さくする。

```js
while (tEl.scrollWidth > box && fs > 13) { fs -= 1.5; tEl.style.fontSize = fs + 'px'; }
```

**原因は端末の「文字サイズ」設定。** Chrome on Android の Text scaling は CSS の px を
そのまま膨らませるので、開発機では収まっている 36px の技名が実機では箱からあふれ、
「薙ぎ払い」が「薙ぎ払」＋「い」に割れていた。

固定値を少し広げるだけでは端末ごとの倍率に追いつかないので、
**`white-space:nowrap` で折り返しを禁止し、実測で縮める**方式にした。
「ドラゴンブレス」のような長い技名でも1行に収まる。

## 操作欄の高さは起動時に実測して固定する

盤面（`.field`）は `flex:1 1 auto` で**残った高さを全部使う**。
そのため下の操作欄の高さが変わるたびにマスが伸び縮みしていた。

実測した揺れ（390×844）：

| 操作欄の状態 | 操作欄 | マス |
|---|---|---|
| 技が1つ／2つ | 65px | 158px |
| 技が3つ（2段になる） | 121px | 144px |
| CPU思考中／行動中 | 106px | 148px |
| ラウンド終了処理中 | 67px | 158px |

自分の番 → CPUの番と進むだけで **1ターンに2回・最大14px（約9%）** 揺れる。これがチラつきの正体。

### なぜ「実測」なのか

固定値をCSSに書くと、**画面サイズと端末の文字サイズ設定で実際の高さが変わる**ため合わなくなる。
そこで `lockPanelHeight()` が、いちばん高くなる状態（技3つ＋案内文）の見えない複製を作って
実際に測り、`--panelH` に入れている。

実装上の落とし穴：`.actpanel` は `position:sticky; bottom:0` なので、
複製に `bottom:auto; height:auto` を付けないと画面いっぱいに伸びて誤った値になる。

### 代償（承知のうえ）

常にいちばん高い状態に合わせるので、技が少ない場面では操作欄の下に空きが出て、
マスは 158px ではなく常に 144px になる。**揺れないことを優先した**という判断。

## 絵の段の文法

段（tier）は**描き方の文法**で区別する。ステータスではなく**絵で格の違いを見せる**ための決めごと。

| 段 | 描き方 |
|---|---|
| 一の段 | 道具を**握って動いている**姿 |
| 二の段 | **道具そのものが特別**であることが分かる姿 |
| 三の段 | **本人は動かず**、周囲の現象や不在で力を示す |

**後光は全段で禁止。** 段の違いを後光で表すと、三段とも同じ絵に見えてしまうため。

この文法は `docs/共通指定.txt` に清書されており、ChatGPT へのプロンプトにも毎回入れる。
段ばしごを1本追加するときは、3体まとめて実寸（136px／352px）で見比べて判断する。

## 実機検証が必須の項目

**Playwright では再現できない**もの。ここに該当する変更は、
必ず配信して kazu の端末（Android）で確認する。「確認できた」と書かない。

| 項目 | 再現できない理由 |
|---|---|
| セーフエリア（カメラ穴・丸い角） | `env(safe-area-inset-*)` がエミュレータでは 0 のまま |
| 端末の「文字サイズ」設定 | Chrome の Text scaling は CSS の px を膨らませる。技名の折り返しの真因だった |
| 日本語の縦書き（`writing-mode`） | 端末のフォントによって効かないことがある（v114 で自動フォールバックを実装） |
| `localStorage` の可否 | `file://` では端末により保存されない |
| 全画面・ホーム画面追加 | ブラウザと端末の実装差が大きい |
| タップ精度・押しやすさ | 誤タップは実機でしか分からない |

なお、開発環境で「縦書きが壊れている」ように見えた件は、
**モック側のフォント指定が誤っていただけ**（`"Noto Sans JP"` は未インストール、
実在するのは `"Noto Sans CJK JP"`）で、ゲーム本体のフォントスタックでは正しく描けていた。
**環境の問題を製品の問題と取り違えない。**
