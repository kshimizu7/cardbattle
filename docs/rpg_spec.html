ARCANA CLASH ／ RPGモード

RPGモード 仕様

これまでの相談をひとつの仕様にまとめました。いちばん重要な決めごとは「ダンジョンは、解く順番から先に作る」という点です。部屋を並べてから鍵を置くのではなく、鍵と扉の連鎖を先に決めて、そこへ部屋をぶら下げます。これをやらないと、開かない扉や取れない鍵が生まれます。

1. 全体の流れ

タイトルでバトルモードとRPGモードを選びます。RPG側の1周はこうです。

酒場 ── パーティ6体を編成、装備を着け替える、傷を癒す
 ↓
クエスト選択 ── 複数のダンジョンから1つ選ぶ（開示文と危険度が見える）
 ↓
ダンジョン ── 部屋を移動 → 語りと選択肢 → 戦闘 → 宝・鍵
 ↓            （持ち帰れなければ全部失う）
帰還 ── 持ち帰った装備とキーアイテムが手元に残る
 ↓
酒場へ戻る ── 強くなった分だけ、上の危険度に挑める

戦闘画面はいまのバトルモードをそのまま使います。敵チームを渡すだけで動くので、演出・音・BGM・キャラ絵が全部そのまま乗ります。

2. マップ ── マス目ではなく、部屋と通路

移動の単位をマス目から「部屋・通路」に変えます。いただいた地図のとおり、大小の部屋と、それをつなぐ通路でダンジョンを作ります。プレイヤーは隣接する部屋や通路をタップして移動します。1回の移動＝1つの場所ぶん。

データとしてはグラフです。場所（ノード）と、つながり（エッジ）だけ持ちます。絵として描くための座標と形も一緒に持たせます。

{ id:'r7', kind:'room',   shape:'circle', x:520, y:80, r:44,
  name:'水鏡の広間',        // 無名なら name:null
  links:['c3','c9'] }
{ id:'c3', kind:'corridor', from:'r7', to:'r2', path:[[520,124],[520,180],[430,180]] }

部屋は矩形か円、通路は折れ線。いまのキャラ絵と同じくSVGで描くので、外部画像は要りません。いただいた地図の見た目（石壁のハッチング、方眼の床）も、SVGのパターンで再現できます。

3. 見えかた ── 灯りと地図

最初はいる場所と、そこから直接つながっている場所だけが見えています。見える範囲は光の強さで決まります。

手段効果入手
松明なしいまいる場所と隣接1つ先まで初期状態
松明（道具）隣接2つ先まで。使うほど短くなる酒場で買う／ダンジョンで拾う
灯火の呪文
魔法使い		その場で3つ先まで。数部屋のあいだ持続魔法使いを連れている
区画の地図ダンジョンの一部の区画が形だけ見える
（出来事の中身は分からない）		宝箱・NPC・死体
全体図全部の形が見える。中身は分からないまれ。強いご褒美

地図で分かるのは「形」だけで、「そこに何があるか」は踏むまで分かりません。ここを分けておくと、地図を手に入れても探索の緊張が残ります。逆に「灯り」は目の前の危険を照らすので、地図と役割が被りません。

4. 通行の制御と、生成の順番

ここがこの仕様の背骨です

ランダム生成で必ず問題になるのが「開かない扉」と「取れない鍵」です。部屋を並べてから鍵を置くと、鍵が扉の向こう側に入り込みます。

これを防ぐには、順番を逆にします。先に「どういう順番で解けるか」の連鎖を決めて、あとからその前後に部屋をぶら下げる。こうすると、鍵が扉の向こうに行くことが構造上ありえなくなります。

解放条件の種類

種類条件語りの例
鍵チームアイテムを1つ持っている錆びた鍵が、ようやく回った
刻印離れた場所の刻印を指定数すべて触れる三つ目の刻印に触れた瞬間、遠くで重い音がした
撃破特定の敵を倒す→ 鍵を落とす崩れ落ちたその手から、鍵がこぼれた
供物アイテムを失う代わりに開く竜のうろこを台座に置くと、扉が沈んだ
一方通行通ると戻れなくなる背後で、床が抜け落ちた
隠し灯り／地図／情報を持っていると見えるようになる灯りをかざすと、壁の継ぎ目が浮かび上がった

「撃破 → 鍵」は、そのモンスターがそこにいる理由になります。ただの障害物ではなく「鍵を守っている者」になるので、裏設定とつながります。

5. 出来事の再現性 ── 3つに分ける

同じ場所に戻ったとき、出来事がどうなるか。ここを3種類に分けます。

種別戻ったとき例持ち方
一度きりもう起きない 落とし穴、宝箱、朽ちた旅人、モンスターの出現done[nodeId]=1
繰り返し何度でも起きる コウモリ、すきま風、遠くの物音、水滴記録しない
キー達成するまで残る 刻印、扉、供物の台座、区画の主gate[gateId]='open'

戦闘から逃げた／負けたときの扱いを決めておく必要があります

「モンスター出現」を一度きりにすると、負けて戻ってきたら敵が消えていることになります。そこで戦闘だけは別扱いにします。勝ったら消える、負けたり逃げたらその場に残る。区画の主（鍵を守る敵）は必ずこの扱いです。

6. アイテム ── 2つの層に分ける

チームアイテム装備アイテム
持ち主パーティ全体（誰かが持つ必要はない）キャラ1体ごと
役割道を開ける強くなる
例鍵、石板、竜のうろこ、日記、地図、松明武器、防具、装飾×2
数制限なし（かさばらない）1体につき4枠
ダンジョン後そのダンジョン専用のものは消える
（記念品として残るものもある）		持ち帰れる
次のダンジョンでも使える

装備は4枠

武器1・防具1・装飾2で設計します。装飾を2つにしたのは、同じ枠を2つ持たせると「どちらを取るか」の判断が生まれるからです。1つだと自動的に最強を挿すだけになります。

効果は、いまの特性の仕組み（selfMod / aura）にそのまま乗せられます。装備を「もう1つの修正元」として足すだけで、エンジン側の計算は変えずに済みます。

{ id:'ironblade', slot:'weapon', name:'鉄の刃',
  mod:{ atk:+2 },  // 攻撃+2
  text:'ありふれた、しかし確かな一振り' }

{ id:'wardring', slot:'trinket', name:'守りの環',
  mod:{ physReduce:1 }, // 受ける物理ダメージ-1
  onlyLine:'人' }       // 人系だけが着けられる、といった制限も置ける

持ち帰れることが、次に潜る理由になります

ダンジョンを1つ攻略するたびに装備が良くなり、その分だけ上の危険度に手が届く。これがRPGモードの推進力です。逆に言うと、持ち帰れなかったときに何を失うかを決めないと、緊張が生まれません。案としては「全滅したら装備は現地に落とす、キーアイテムだけ失う、途中で引き返せば全部持って帰れる」あたりが素直だと思います。ここは体験の要なので、相談させてください。

7. 効果と状態異常

出来事の結果は、すべて「誰に」×「どのくらい」を持ちます。デモに実装済みです。

効果誰にどのくらい
ダメージ／回復 全員／前衛／後衛／1人／2人／いちばん傷ついた者 小 2〜4　中 5〜8　大 9〜14
状態異常同上毒・出血・恐怖・暗闇・弱体・鈍足／残り部屋数で持続
状態回復同上特定の1種、またはすべて
戦闘初撃の対象（1人／前衛／全員） 先制の向き（こちら／対等／敵）× 規模（小勢・一群・主）

状態異常は二階建てにする必要があります

いまのエンジンの状態異常（呪詛・鈍足・弱体・防御・障壁の5種）は、戦闘が終わると消える作りです。RPGでは探索中ずっと続く層が別に要ります。

探索の状態異常は、戦闘開始時に戦闘側へ写します。毒を受けたまま戦闘に入れば、戦闘中も毒のまま。戦闘が終わると戦闘側は消えますが、探索側は残る——という二段構えにします。

8. データの持ち方

rpg: {
  party:   [ {id:'knight', hp:22, max:22, equip:{weapon:'ironblade', armor:null,
                                                 trinket1:'wardring', trinket2:null}}, … ],
  stash:   ['ironblade','wardring', …],   // 酒場に置いてある装備
  cleared: {'beast':2, 'mine':1},         // 踏破回数
  run: {                                  // 潜っている最中だけ存在する
    dungeon:'mine', seed:948213,
    at:'r7', seen:{r1:1,r7:1,c3:1},
    done:{r4:1}, gate:{g1:'open'},
    bag:['key_rust'],  status:{knight:{poison:3}},
    torch:2, alert:1
  }
}
  • ダンジョンは種（シード）から作り直します。マップ全体を保存する必要はなく、seed と「どこを見たか・何を開けたか」だけ持てば復元できます。数KBに収まります
  • セーブの版番号と移行処理を最初に入れます。いまのセーブは v:1 固定で移行の仕組みがありません。RPGは項目が育っていくので、ここを先に作らないと後で必ず詰まります
  • 引き継ぎコードを前に出します。localStorage は消えます。v43で入れた対戦の再現データと同じ仕組みで、ダンジョンを1つ攻略するたびにコードの保存を促すのが安全です

9. 戦闘との接続

  • 敵チームは、いまのカードから組みます。ダンジョンの設定に合う顔ぶれを選ぶだけ（獣の洞なら人狼・イエティ、神域なら竜・聖騎士系）。新しい敵データは要りません
  • 先制はコイン（coin）で表現できます。こちらが奇襲＝coin:0、敵に先制される＝coin:1。エンジンを変えずに済みます
  • 傷は持ち越します。createState に渡すときにHPの初期値を上書きする口が要ります（いまは満タン固定）。ここだけ小さな改修が必要です
  • 装備と探索の状態異常も、戦闘開始時に反映します

10. 作る順番（改訂）

  1. 部屋と通路のマップで、語りと選択肢を遊べるようにする 確かめたいこと：この遊びは面白いのか 固定の1ダンジョン、鍵は1種類だけ、アイテムなし、HP全快。マス目から部屋・通路への作り替えと、灯りによる段階的な開示までを含みます。ここが面白くなければ後が全部無駄になるので、最初に置きます
  2. 生成と解放条件 確かめたいこと：毎回ちがうと感じられるか／詰まないか 区画と解錠の連鎖から生成。鍵・刻印・撃破・供物の4種の扉。生成後に必ず「入口から最奥まで到達できるか」を検査し、通らなければ作り直します。出来事の3分類もここで入れます
  3. アイテムと装備 確かめたいこと：また潜る理由になるか チームアイテムと4枠の装備。酒場の装備画面。セーブの版番号・移行処理・引き継ぎコードの前出しも必ずここで
  4. 持ち越しと育成 確かめたいこと：長く遊べるか HPの持ち越し、探索の状態異常、酒場での回復、複数ダンジョンの解放。失うものの設計はここで確定します

11. 決めてほしいこと

  • 全滅したとき、何を失うか。装備を落とす／キーアイテムだけ失う／何も失わない。ここでRPGの手ざわりがほぼ決まります。私は「装備は落とす、ただし引き返せば全部持ち帰れる」を推します——引き返す判断そのものが遊びになるからです
  • 1回のダンジョンの長さ。いまのデモは14部屋で8分ほど。スマホで1回20〜30分を想定するなら、25〜35部屋・区画3つくらいが目安です
  • 装飾2枠でいいか。武器・防具・装飾×2の4枠。増やすほど組み合わせは増えますが、画面も判断も重くなります
  • Phase 1 の範囲でまず作ってよいか。部屋と通路・灯り・鍵1種・語りと選択肢まで。ここまでで「面白いか」の判定はできます
