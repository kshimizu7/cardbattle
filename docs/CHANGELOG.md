## v32 — 2026-08-22

**バグ修正（重要なものを含む）**

### 🐞 前進したキャラが盤面から消え、見えないまま行動していた（重大）

ご指摘いただいた2件は**同じ原因**でした。

前衛が倒れた瞬間に後衛が繰り上がる仕様（v29）で、**倒れたキャラは前衛マスに残ったまま**
だったため、繰り上がった生存キャラと**同じマスに2体が重なって**いました。
どちらが描かれるかは内部の並び順しだいで、

- 死体が描かれる → 生きているキャラが**盤面から消える**（＝見えないのに手番が回る）
- 生存キャラが描かれる → **死体が消える**（＝撃破された表示が2種類あるように見える）

200試合を機械的に検査したところ、**マスの重複が 6,067回**、うち
**生存キャラが盤面から消えるケースが 148回**発生していました。

**修正：**生者が前に出るとき、**倒れたキャラを空いた後衛マスへ下げる**ようにしました。
これで1マスに1体だけになります。検査結果は **6,067回 → 0回**。
描画側にも「重なっていたら生存キャラを優先して描く」保険を入れています。

### 🐞 演出が1つ失敗すると、戦闘全体が止まっていた

演出の再生に例外処理がなく、途中で1つ失敗すると**以降のダメージ表示も進行も打ち切られて**
いました。複数体攻撃の2体目以降が止まって見える原因になり得ます。
1つ失敗しても飛ばして続行するようにしました。

なお**エンジン側は正常**で、業火のブレス・薙ぎ払いとも
400回中400回、全員にダメージが通ることを確認済みです（途中で前進が起きる状況でも）。

### 🐞 交戦ラインの矢羽根が一度も出ていなかった

v31で追加した攻撃方向の表示が、参照するデータ名を間違えており動いていませんでした。
縦横どちらでも発火することを確認しました。

### 🔄 プレイ中に端末を回してもレイアウトが切り替わるように

演出中に回すと切り替わらないままでした。**クラスの付け替えだけで縦横を入れ替える**方式に変え、
演出中でも安全に切り替わります。

### 📱 iPad mini / Edge のちらつき（アドレスバーが見えているとき）

画面の高さに `dvh` を使っていたため、**アドレスバーが出入りするたびに高さが変わり**

**横並び対戦モード ／ 卓上対面モードの撤去**

### 🤝 横並び対戦

向かい合わず**隣に並んで座り、端末を横にして左右で戦う**モード。

対面配置（v23/v24）は行き詰まりました。**このゲームは毎ターン相手の数字を読まないと打てない**のに、
向かい合うと相手側が必ず逆さまになるためです。調べた既存アプリ（Two Player Chess Basic の対称駒、
Easy Chess 2P の二重盤、MTGライフカウンターの片側専用表示）は、どれも「相手側を読ませない」設計で
問題を**回避**していました。

横並びなら**画面の向きがひとつだけ**になり、逆さまの文字が一つも出ません。

```
┌────────────────────────────────────┐
│ P1 後衛│前衛 ‖ 前衛│後衛 P2        │
│   □    │  □  ‖  □  │  □           │
│   □    │  □  ‖  □  │  □           │
│   □    │  □  ‖  □  │  □           │
└────────────────────────────────────┘
  ↑左に座る人            ↑右に座る人
```

- **端末を横にすると自動で切り替わります**（縦に戻すと従来表示）
- 盤面の意味は不変。後衛が外側、前衛が内側（交戦ラインに接する）。
  近接の「正面」は同じ高さの敵で、左右一直線になるぶん縦積みより見やすい
- ゲームエンジンは変更なし。**表示だけの変更**

### 📍 操作パネルの位置を選べます
